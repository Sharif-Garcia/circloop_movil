# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

CIRCLOOP ("Sistema de Devolución y Recompensa") is a Flutter mobile app for a university recycling/reward system (users have institutional `@unicesar.edu.co` emails and accumulate points). All identifiers, UI strings, and comments are in **Spanish** — keep new code consistent (e.g. `iniciarSesion`, `obtenerUsuarios`, `correoInstitucional`).

## Commands

```bash
flutter pub get                          # install dependencies
flutter run                              # run the app on a connected device/emulator
flutter analyze                          # lint (flutter_lints via analysis_options.yaml)
flutter test                             # run all tests
flutter test test/login_test.dart        # run a single test file
flutter test --plain-name "<test name>"  # run a single test by name

dart run flutter_launcher_icons          # regenerate app icons (config: flutter_launcher_icons.yaml)
dart run flutter_native_splash:create    # regenerate native launch splash (config: flutter_native_splash.yaml)
```

App icons and the native launch splash for Android/iOS/web are generated from the square images in `assets/launcher/` (derived from `assets/images/logo_original.png`; not bundled in the app). Don't hand-edit the generated files under `android/app/src/main/res/`, `ios/Runner/Assets.xcassets/` or `web/icons`/`web/splash` — change the source image and rerun the commands.

Widget tests (`test/*_test.dart`) exercise full screen flows against the real JSON data (test users in `assets/data/usuarios.json`, password `123456`). Use the shared helpers in `test/helpers/pruebas.dart`: call `configurarPruebas()` at the top of `main()`, mount screens with `abrirPantalla`, and use `entrarComoAna`/`irAPestana` for comunidad-panel tests. They exist because of two gotchas with `rootBundle`: the load is real async, so waiting needs `tester.runAsync` + `pump` loops (`esperarA`/`esperarHasta`; plain `pumpAndSettle` times out), and a cached load from a previous test hangs forever in the next one (hence `rootBundle.clear()` in `setUp`).

## Architecture

Layered structure under `lib/`, with state managed by **Riverpod 3** (`flutter_riverpod`):

- `main.dart` wraps the app in `ProviderScope`; `app.dart` (`MyApp`) builds the `MaterialApp` with `AppTheme.lightTheme` and `SplashScreen` as home. Flow: `SplashScreen` (3s) → `OnboardingScreen` → `LoginScreen` → `InicioRolScreen` (temporary per-role panel; logout returns to login), each via `Navigator.pushReplacement`. `LoginScreen` navigates from a `ref.listen` on `authProvider` when it becomes `data(usuario)` to `pantallaInicioPorRol(usuario)` (`screens/auth/sesion.dart`, which also has the shared `cerrarSesion(context, ref)`); it also `push`es `RecuperarContrasenaScreen` and `RegistroScreen`, which `pop` back to it when done. There is no router yet.
- Role panels: rol 1 → `PanelComunidadScreen` (`screens/comunidad/`); other roles still get the temporary `InicioRolScreen` until they have their own. A panel is a `PanelNavegacion` (`widgets/navegacion/`) with a `BarraSuperior` and a list of `SeccionPanel` tabs kept alive in an `IndexedStack`; widgets inside switch tabs with `PanelNavegacion.of(context).irA(i)` (comunidad tab indices in `PestanaComunidad`). Shared tabs live in `screens/comunes/` (`EnConstruccionScreen` for unbuilt tabs, and `PerfilScreen` — the single profile for all roles, with `EditarPerfilScreen` and logout; roles add their own part via `PerfilScreen(contenidoRol: ...)`, e.g. `ResumenPerfilComunidad`). `BarraSuperior(pestanaPerfil: i)` makes the avatar jump to that tab. Tab content never has its own `Scaffold`/`AppBar`; a tab's FAB goes in `SeccionPanel(botonFlotante: ...)` so the panel's Scaffold moves it above SnackBars (a nested Scaffold's FAB gets covered by them). Only screens `push`ed over the panel (historial, `CodigoQrScreen`, `EditarPerfilScreen`) have their own `Scaffold` + `BotonVolver`. New role panel = new `screens/<rol>/panel_<rol>_screen.dart` + a case in `pantallaInicioPorRol`.
- `models/` — plain immutable classes with a `fromJson` factory (no code generation). Relationships are by integer id (`Usuario.rolId`, `Usuario.carreraId`, `Carrera` → `Facultad`).
- `services/` — one service per model that loads data from the bundled JSON files in `assets/data/` via `rootBundle.loadString` + `jsonDecode`. **There is no backend**; these JSON files are the mock data source (users, roles, careers, faculties). New data files must live in `assets/data/` (already registered in `pubspec.yaml`). Since assets are read-only, writes are simulated in memory in static fields of `UsuarioService` (`registrar` appends to a list merged into `obtenerUsuarios`; `actualizarContrasena` keeps a map checked by `iniciarSesion`; lost on restart; reset in tests via `reiniciarDatosEnMemoria`). These methods are the single place to swap in backend calls (marked `TODO`) — screens and providers shouldn't need changes. Emails are compared trimmed/lowercased. Expected, user-facing failures are thrown as `ServicioException(mensaje)` (`services/servicio_exception.dart`); providers show `e.mensaje` for those and `AppStrings.errorGeneral` for anything else.
- `services/codigo_verificacion/` — password-reset codes behind the `CodigoVerificacionService` interface. `CodigoVerificacionSimulado` (in use) generates the code in memory and returns it so the screen shows it ("Modo de prueba"); `CodigoVerificacionCorreo` is the stub for real email delivery (must go through a backend — never put mail credentials in the app). Swap implementations only in `codigoVerificacionServiceProvider` (`providers/recuperar_contrasena_provider.dart`).
- `providers/` — Riverpod `Notifier`s exposing `AsyncValue` state. `authProvider` (`AuthNotifier`) holds `AsyncValue<Usuario?>`: `data(null)` = logged out, `loading` during login, `error(<Spanish message>)` for bad credentials/inactive user. `registroProvider` (autoDispose) follows the same `AsyncValue<Usuario?>` pattern. `carrerasProvider` is a cached `FutureProvider` (sorted careers for dropdowns). `recuperarContrasenaProvider` (autoDispose) holds an immutable `EstadoRecuperacion` (step enum, `cargando`, one-shot `error`) that the screen reacts to via `ref.listen`. Notifiers instantiate `UsuarioService` directly; swappable services are exposed as `Provider`s (e.g. `codigoVerificacionServiceProvider`), which tests can override. After an `await` in a notifier, check `ref.mounted` before setting `state`.
- `screens/` — grouped by feature (`screens/auth/`). Screens are `ConsumerStatefulWidget`s that `ref.watch` providers for UI state and `ref.listen` to surface errors via `SnackBar`.
- `utils/` — design tokens and helpers: `AppColors` (palette), `AppSizes` (spacing/icon sizes like `AppSizes.md`, `AppSizes.iconXl`), `AppTheme` (Material 3 `ColorScheme` built from `AppColors`), `Validators` (static form validators returning Spanish error strings; single source for rules like `longitudMinimaContrasena` = 8 with letters+numbers, shared by registration and password reset — tests should assert on `Validators.x(badInput)!` rather than copying messages), `AppImages` (asset paths under `assets/images/`), `AppStrings` (all UI texts, incl. functions for interpolated ones like `bienvenida(nombre)`), `AppRol` (per-role name/panel title/icon/color, looked up with `AppRol.porId(usuario.rolId)`). Use these instead of hardcoded colors/spacing/paths/texts.
- `widgets/` — reusable widgets, grouped by kind (check here before writing UI in a screen):
  - `comunes/`: `AppImagen` (asset image with icon fallback if the file is missing), `AppLogo`, `AppMarca` (small logo + name), `AppTarjeta` (white bordered card), `EncabezadoSeccion` (left-aligned title + subtitle), `IndicadorPaginas` (step dots), `AppMensaje.exito/error/aviso/info` (colored SnackBars), `mostrarDialogoExito`.
  - `botones/`: `BotonPrimario` (full-width, loading state), `BotonVolver`, `EnlaceTexto` ("¿Ya tienes cuenta? **Inicia sesión**"; uses `Wrap` so it never overflows).
  - `formularios/`: `CampoTexto` (label + `TextFormField`), `CampoContrasena` (show/hide toggle), `CampoCodigo` (one digit per box), `CampoSelector<T>` (labeled dropdown), `CasillaAceptacion` (checkbox that is a `FormField<bool>`, so it validates with the form). All accept `validator`s and most a `habilitado` flag.
  - `comunes/` also: `AvatarUsuario` (photo or initials), `Etiqueta` (colored pill), `IndicadorEstadistica`, `TituloSeccion` (block title + optional link), `ItemLista` (generic card row for any list), `EstadoVacio` (empty/error/pending state).
  - `botones/` also: `BotonAccion` (tinted quick-action card, meant for a row of `Expanded` on any role's home).
  - `navegacion/`: `PanelNavegacion` + `SeccionPanel`, `BarraSuperior` (avatar + brand, optional points chip, notifications).
  - `auth/`: widgets specific to auth screens (`EncabezadoAuth`: logo in circle + title + subtitle).
  - `comunidad/`: widgets specific to the comunidad panel (`TarjetaNivel`, `TarjetaImpacto`, `ItemEntrega`).
- Data is stored raw (numbers, ISO dates, keys like `"plastico"`) and formatted in the UI: `Formatos` (`utils/formatos.dart`: `entero` → "1.250", `kilos` → "14,5 kg", `fechaRelativa` → "Hoy, 10:45 AM"), `AppMaterial.porClave` (`utils/app_materiales.dart`, like `AppRol`), `NivelEco` (`models/nivel_eco.dart`, gamification levels from `puntosHistoricos`). `ProgresoEco.desde(usuario, entregas, {ahora})` is the single place that totals kg/CO₂/deliveries per material/points this month (exposed as `progresoUsuarioProvider`). The user's QR ("Código Eco-Identificador", scanned by operators) comes from `EcoIdentificadorService` (`CIRC-000001`; `idDesdeCodigo` parses it back) via `ecoIdentificadorProvider`, rendered with `qr_flutter`'s `QrImageView`. Material filters use `AppMaterial.claves`/`nombreCorto` with `SelectorChips`. Gotcha: a state-dependent `WidgetStateTextStyle` in `chipTheme.labelStyle` is lost inside `ChoiceChip` (label ends up with no color → invisible); `chipTheme` holds only the base style and `SelectorChips` sets the selected/unselected label color per chip. Badges (`insignias.json`) store rules (`criterio` + `meta`), never earned state; `Insignia.lograda(progreso)` evaluates them (`insigniasUsuarioProvider`), icons resolved by name via `AppIconos`. `rankingComunidadProvider`/`puestoRankingProvider` rank comunidad users by `puntosHistoricos`. Profile edits go through `editarPerfilProvider` → `UsuarioService.actualizarUsuario` (in-memory override) → `authProvider.notifier.actualizarUsuario`, so every screen sees the new data. Rewards: `premios.json` → `Premio` (category keys resolved by `AppCategoriaPremio`, like `AppMaterial`) → `premiosProvider`; `canjes.json` + in-memory → `Canje` → `canjesUsuarioProvider`. `CanjeService.canjear` validates points (`ServicioException`), deducts them via `UsuarioService.actualizarUsuario`, generates a `CJ-XXXXXX` code; `canjearProvider` then pushes the updated user into `authProvider`. Any action that changes the user (points, profile) must end with `authProvider.notifier.actualizarUsuario`. `Premio` carries DB-driven `imagenUrl`, `stock` (`null` = unlimited; `agotado`/`quedanPocos`) and `activo` (inactive ones are filtered out in `PremioService`); canjes check and decrement stock (`PremioService.descontarStock`, in-memory) and `canjearProvider` invalidates `premiosProvider`. Point transfers: `TransferenciaService.transferir` (recipient must exist, be comunidad + active, not self; only `puntosTotales` move, never `puntosHistoricos`) via `transferirProvider`, UI in `TransferirPuntosScreen`. Notifications (all roles): `notificaciones.json` → `Notificacion` (type keys via `AppTipoNotificacion`) → `NotificacionService` (read state + new ones in memory) → `notificacionesProvider`, an `AsyncNotifierProvider` (list + `marcarLeida`/`marcarTodasLeidas` with optimistic `state` updates; rebuilds when `authProvider` changes) and `notificacionesNoLeidasProvider` for the bell `Badge` in `BarraSuperior`, which opens `NotificacionesScreen`. Services that do something a user should hear about create the notification themselves (`CanjeService` → own user, `TransferenciaService` → recipient) via `NotificacionService().crear(...)`; with a backend the server does it. Content images always come from the DB as URLs and render with `ImagenRemota` (spinner + icon fallback); `AppImagen` is only for local brand assets (logo, mascot). Format checks live in `Validators`; business rules are re-checked in services with `ServicioException` (and must be re-checked by the future backend). QR codes are always drawn with the `CodigoQr` widget; confirmations use `mostrarDialogoConfirmacion`. Tests reset the in-memory data of every service that has it (`UsuarioService`, `CanjeService`, `PremioService`, `TransferenciaService`, `NotificacionService`) in `configurarPruebas` — add new ones there. `entregas.json` → `Entrega` → `EntregaService` → `entregasUsuarioProvider` (current user's deliveries); `carreraUsuarioProvider` / `facultadesProvider` for the user's academic info.
- Styling is inherited from `AppTheme`: button styles (`filledButtonTheme`/`elevatedButtonTheme`/`textButtonTheme`), `inputDecorationTheme` (field fill/borders), `snackBarTheme` (floating), `appBarTheme`, `navigationBarTheme`, and `textTheme` (`headlineMedium`, `headlineSmall`, `titleLarge`, `titleMedium`, `titleSmall`, `bodyMedium`, `bodySmall`, `labelMedium`). Screens should use `Theme.of(context).textTheme.*`, themed buttons and plain `InputDecoration`s rather than inline `TextStyle`/`styleFrom`/borders.
- Static screen content (e.g. onboarding steps in `screens/onboarding/onboarding_pasos.dart`) lives as `const` model lists next to the screen, not in JSON.

Roles (from `assets/data/roles.json`): `1 comunidad`, `2 operador`, `3 punto_canje`, `4 administrador`, referenced by `Usuario.rolId` (constants `AppRol.comunidad`, etc.). Auth errors are deliberately generic ("Correo o contraseña incorrectos.", and password reset answers the same for unregistered emails) — don't reveal whether an email is registered. Registration is the one exception (it must say the email is taken). New accounts get role `AppRol.comunidad`.

Imports mix `package:circloop_movil/...` and relative paths; either is used in the codebase.
